## About

`poagen/client-runtime` is the small, dependency-light package every client
[poagen](https://github.com/mlavrinenko/poagen) generates depends on at
runtime. It carries no code generation logic of its own — nothing here
knows what an OpenAPI document is — only the machinery a generated client
calls into:

* **[`Endpoint`](src/Contract/Endpoint.php) / [`ResponseType`](src/Contract/ResponseType.php)** —
  a generated operation describes its request as an `Endpoint` and the
  shape it expects back as a `ResponseType`, and hands both to an injected
  [`TransportInterface`](src/Contract/TransportInterface.php).
* **[`Envelope`](src/Contract/Envelope.php)** — every operation returns one,
  carrying the HTTP status the wire sent, the body hydrated into the shape
  the document declared for that status, and the PSR-7 response both came
  from. A declared status is a return value, never a throw; a profile's
  `Generated\ApiException` is raised only for a status the document
  declared nothing for, or a declared body that failed to hydrate.
* **[`Marshaller`](src/Marshal/Marshaller.php) / [`Hydrator`](src/Marshal/Hydrator.php)** —
  a shared pair driving every (de)serialisation via phpdoc types and a
  small set of runtime attributes (`#[WireName]`, `#[Discriminator]`,
  `#[AdditionalProperties]`, …). Model classes generated against this
  runtime carry no generator boilerplate of their own.
* **Replaceable** — every runtime collaborator a generated file names is an
  interface under [`src/Contract/`](src/Contract/), and generated type-hints
  point at those rather than at implementations. Supply your own hydrator,
  marshaller, XML writer, descriptor parser or error policy — or your own
  transport for all of it.

This package is a consumer of PSR-7 / PSR-17 / PSR-18 only — plug in
Guzzle, Symfony HTTP Client, or anything else that implements them.

## Installation

```bash
composer require poagen/client-runtime
```

Not on Packagist yet — that is tracked separately as
`publish-the-runtime-package-to-packagist` in the parent
[poagen](https://github.com/mlavrinenko/poagen) monorepo's own task tracker.

## Development

This directory is developed inside the
[poagen monorepo](https://github.com/mlavrinenko/poagen), but is fully
self-contained: its `composer.json`, test suite, and every lint/static
analysis/formatting config here are scoped to this tree alone, with no path
escaping it. `git subtree split --prefix=runtime` of the parent repository
produces exactly this directory as a standalone, checkable package —
verified by installing and gating that split in isolation, with the
generator absent (`bundle-the-runtime-package-with-its-own-ci-tooling`).

```bash
composer install
just check    # lint + test with the coverage floor enforced
just format   # auto-fix code style
```
